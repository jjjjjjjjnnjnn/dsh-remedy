## dsh-remedy 0.4.9

### Added

- **P-0035 — a patch-layer row can no longer promise a module nothing resolved.** Every `name:`
  in `cordis.patch.yml` is resolved against the package's own `exports` and against the built
  file. Upstream discussion #12318 is the negative control: a config that kept a removed subpath
  export reported `never started`, and every session resume failed while the UI looked like
  "one broken session". Four tests, three of them controls. Zero runtime bytes.

### Fixed

- **P-0034 — a turn that failed with `MALFORMED_RESPONSE` is no longer booked as a quiet one.**
  `isFusionFailure` reads the failure *code*, and the finish path read that one answer as
  "was this failure already counted?". So every `MALFORMED_RESPONSE` that had nothing to do with
  arguments was booked as silence. Upstream discussion #11337 is the measured shape: a benign
  prompt produced a reasoning block, the Messages stream closed with `stop_reason: "refusal"`,
  the adapter raised `unsupported stop reason refusal`, the turn died — and the journal recorded
  no error, no refusal, nothing. Both failure exits now count an error unless a refusal at this
  seam already explained the failure; a refusal is still not counted twice.

### Changed

- Six leads closed with a reason instead of a patch. L-0033 is the same empty-identity shape
  P-0033 already fixes. L-0034 is out-of-seam: the adapter substitutes `{}` for malformed
  arguments before this seam can see the original text. L-0024 needed no change, because
  `type:'json'` compiles to an untyped schema and the attribution proof already treats an
  undeclared type as undecidable. L-0036 stays `watching`: this machine measured six attempts
  with no `finish` out of 9401, and nothing here proves the host treats such a stream as a
  success.
