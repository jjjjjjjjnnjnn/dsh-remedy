## dsh-remedy 0.4.6

### Fixed

- **The map a successor reads was compared with nothing.** The live handoff called `v0.4.2` the newest release after `v0.4.3`, `v0.4.4` and `v0.4.5` had shipped, its five-minute check still commented `# 0.4.1`, and `docs/PUBLISH.md` still said npm was at `0.4.2`. Each line is now compared with the version the packages ship, and the byte row is compared with the measured build (`handoff-bytes` in the size gate).
- **The same section taught a payment that cannot work.** It said a new patch should be paid for by splitting modules by load path. The total cap is the sum of both subtotals, so a split moves bytes between halves and pays none of the total; the advice now says delete or de-duplicate, or sign a cap change.
- **A fragment's name was checked against `required` and nothing else.** Reading the compiler that builds the request showed the parameter schemas are open (`dsh-tools`), so "every key must be declared" would have been an over-claim. The proof now also uses a closed schema and a declared value that breaks its own `type`, `enum` or `const`; a keyword the module cannot decide never produces a refusal.
- **A repaired event could report another repair's count.** Unattributed fragments were counted across the whole stream, so a stream with two fused blocks reported the first block's count on both events. Counts are per decision now.

### Added

- `fragmentFit()` in the engine returns `fits` / `foreign` / `unproven`; the plugin only finds the declaration and defers the proof.
- The `repaired` event carries `unproven: <n>` when the schema could not speak, so the journal stops implying the name was proven.
- Governance rules for the live release row, the five-minute `npm view` comments, the `currently` version in `docs/PUBLISH.md`, and the byte account in the handoff.

### Changed

- The attribution check moved from the plugin into the engine (`fragmentFit()`). The plugin now only finds the declaration and parses nothing, so its emitted bytes fell even though the patch adds a proof; no byte cap moved.

### Notes

- This release carries 30 patches: 3 `verified` and 27 `tested`.
- Byte budget: residency 41551 of 44000, CLI 41362 of 42000, total 82913 of 83000 — eighty-seven bytes of headroom. No cap moved.
