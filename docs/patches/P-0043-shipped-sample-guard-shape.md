# P-0043 — The guard that protects a fixture could not see the fixture's shape, and 0.4.13 shipped the account name

**Status**: `tested`  **Severity**: `major`  **Surface**: `scripts`  **Depends on**: P-0028, P-0038

## Symptom

The published **0.4.13** tarball carries this machine's account name:

```
$ tar -xOzf dsh-remedy-0.4.13.tgz package/fixtures/toolcall-fusion/bare-code-value.json | grep -c <account>
1
```

The name sits inside `fixtures/toolcall-fusion/bare-code-value.json`, in the
escaped program the fixture quotes. **P-0028 exists exactly to prevent this**, and
its governance test was green on that file.

## Root cause — a guard narrower than the data it guards

`tests/governance/shipped-samples.test.ts` forbade the shape

```
[A-Za-z]:[\\/]{1,2}Users[\\/]
```

i.e. **one or two** separators between the drive letter and `Users`. The fixture is
a **JSON string**: one backslash in the model's program becomes four in the file
(`C:\\\\\\\\Users\\\\\\\\<name>`). Four is outside `{1,2}`, so the guard answered
`false` on the one file it was written for.

Measured on the pre-fix tree (`.tmp/r53-guard-red.mjs`):

| line | guard (`{1,2}`) | widened (`+`) |
|---|---|---|
| `C:\Users\<name>` (1) | sees it | sees it |
| `C:\\\\Users\\\\<name>` (4, the fixture) | **misses it** | sees it |

Second half, same family: **nothing** checked *tracked* result artifacts for a bare
account token. `data/results/live-linux-2026-11-15T15-00-00.000Z.json` recorded an
`ls -l` line verbatim and that line reads `… 1 <name> <name> 25 …`. There is no drive
letter and no `Users` segment in it, so the path-shaped guard could not see it either,
and `redact()` does not treat a bare word as a path — inventing a rule for "any word
that looks like a user" would be guessing.

## What changed

1. **The guard now accepts one or more separators** and requires a non-letter before
   the drive letter, so `file:///Users/<name>` (a URL scheme quoted in prose about
   macOS) is still not flagged. Its negative control gained the escaped shape and the
   URL shape, so a future narrowing fails in the same test.
2. **`bare-code-value.json` and its unit test use `<home>`**, which is the placeholder
   P-0028 already established for the other fixture. The `note` now says the file is
   no longer a byte-identical copy and why; the shape it exists for — a bare,
   unquoted multi-line value — is untouched, and `verify` still prints
   `PASS  bare-code-value.json — repaired` (8 fixtures).
3. **A new guard checks every tracked artifact for the account the machine runs as**,
   read from `USERNAME` / `USER` rather than hard-coded. It walks `data/results/`,
   which is where a recorder's raw text can reach a file, and it reports the file
   path instead of a count.
4. **The one leaking artifact was repaired**: `stranger_install.bin_line` becomes
   `<user> <user>`, a `redaction_repair` field records what moved and why, and the
   sibling `.sha256` names the new bytes — the same shape `scripts/redact_artifacts.mjs`
   uses (provenance fields untouched, because this is a byte repair, not a
   re-measurement).
5. `packages/plugin/fixtures/` was regenerated by `sync_fixtures.mjs`, and the
   `checksums.json` manifest still verifies (`fixtures-sync.test.ts`).

## Red first, measured

| rule | before the fix |
|---|---|
| shipped-samples (widened) | **fails**, naming `CHANGELOG.md`, `data/fixtures/…/bare-code-value.json`, `packages/plugin/fixtures/…/bare-code-value.json` |
| result artifacts name no real account (new) | **fails**, naming `data/results/live-linux-2026-11-15T15-00-00.000Z.json` |

Both are green after. `pnpm run test` moved **361 → 362** tests.

## What this does NOT fix

- **The published 0.4.13 tarball still carries the name.** A published version cannot
  be rewritten; the fix ships in the next release, and the release note for 0.4.13
  stays as it was (P-0041's precedent: fix forward, do not rewrite history).
- **The guard is a test, not a writer.** A future recorder that writes a bare account
  token into an artifact is caught after the fact, not prevented; the writer-side rule
  is still `redact()`'s path shapes only.
- **`USERNAME` / `USER` are the guard's input.** A CI run with no such variable scans
  for the literal `NO_ACCOUNT_IN_ENV` and therefore finds nothing — the guard cannot
  prove absence of an account it does not know. That is a limit, not a pass.
- **Other machines' artifacts** were produced elsewhere and are not in this repository.

## Reproduction

```
node .tmp/r53-guard-red.mjs                 # the two guards against the pre-fix shapes
node --test tests/governance/shipped-samples.test.ts
node scripts/sync_fixtures.mjs --check
node packages/plugin/dist/cli.js verify     # OK 8 fixture(s)
tar -xOzf .tmp/r53-pack/dsh-remedy-0.4.13.tgz package/fixtures/toolcall-fusion/bare-code-value.json | grep -c <account>   # pre-fix: 1
```
