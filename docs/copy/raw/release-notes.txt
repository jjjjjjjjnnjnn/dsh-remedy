## dsh-remedy 0.4.15

### Added

- **P-0044 — a truncated turn now says whether it answered anyone.** `scan` has counted every
  `turn/end` since P-0006 and never asked the second half of the question. On this machine that
  gap was not hypothetical: 88 `max-tokens` turns were reported, and **88** of them ended with
  no `text` block and no `tool-call` — the user saw an empty bubble in every case.
- The rule lives in `packages/core/src/answer.ts`: a `tool-call` answers, a `text` block answers
  only when it is not whitespace, a block type the rule does not know does not answer, and only
  a turn's **last step** decides. The scanner and the evidence recorder call the same function.
- `scan` prints `truncated_without_answer` on the human line, in `--json` and in `--out`; every
  `rows` entry carries its own count, so a total stays auditable backwards.

### Changed

- **The registry ledger was compacted again, and no cap moved.** 28 records were shortened to
  the ledger fields plus a one-sentence `symptom`, a one-sentence `rootCause` and two to four
  short `limits`; the long form stays in `docs/patches/`. `registry.js` went from 67991 to
  63955 of 68000 bytes, and the patch record for P-0044 then spent part of that room. Every
  concrete token removed (version numbers, hashes, `file:line`, failure codes) was checked
  against its own patch document before deletion.
- The P-0044 record no longer carries an empty `switchKey`, because an optional field set to
  `undefined` still reaches the snapshot and reads like a switch key that does not exist.

### Fixed

- Nothing: this release adds a counter and pays for it. No repair path, verdict or exit code
  changed, and a truncation is still never repaired.

- This release carries 44 patches: 6 `verified` and 38 `tested`.
- Byte budget: residency 40895 of 44000, CLI 41962 of 42000, total 82857 of 83000; engine
