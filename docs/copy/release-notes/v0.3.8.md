## dsh-remedy 0.3.8

### Added

- P-0011: the plugin's second seam, `agent/request-error`, had **no test at all** since 0.2.0. It also called `next()` and then overrode whatever the default chain returned, and kept its retry budget in a map that was never pruned, so a long-lived desktop process kept one entry per step forever. It now follows the contract the runtime documents: a handling listener returns `{ kind: 'retry' }` **without calling `next()`**, and a listener that does not own the decision returns `next()`. The budget is a bounded cache of 256 entries, and the listener exposes `cacheSize()` so a test proves the bound. Nine tests pin every branch.
- P-0013: 37 turns on one machine died with `UNSUPPORTED_REASONING_EFFORT` — `provider "opendesign" model "deepseek-v4.1-flash-eco" does not support reasoning effort "xhigh"` — across three workspaces, eleven sessions and two days, and the journal said nothing. `repair-stream` is mounted on `llm/stream`, which only runs after a request is dispatched, so a step refused during preparation could never reach it. Those classes are now named once per step and code and never retried, and `preflightEffort` can answer `ok` / `refuse` / `unknown` for a configured effort before a token is spent.
- `dsh-remedy explain`: a new command that prints, per failure class, how often this machine hit it, which patch covers it, and whether that patch is switched on in the profile you name.

### Changed

- P-0012: the byte budget was one number describing two load paths — the modules a mounted plugin loads at startup, and the modules only a command loads. A daemon pays the first half on every session and the second half never, so one cap made every resident byte compete with CLI code. It is now three checks: residency 41075 of 44000 bytes, cli 40665 of 42000 bytes, and a total of 81740 of 83000 bytes, with a rule that every emitted module belongs to exactly one of the first two and a governance test that walks the real module graph in both directions.
- The copy channel's transport is retired. Outward files are written in the session that does the work, and the copy gate enforces the property the channel existed for — every prose number traceable to the fact pack, every artifact's bytes unchanged — instead of checking the identity of the author.

### Fixed

- The largest non-fusion failure class on the measured machine no longer kills a turn silently, and the second seam is no longer unverified code that only ran when someone switched a non-default option on.

### Package size

- `dsh-remedy@0.3.8`: 35898 bytes compressed, 35 files, 117750 bytes unpacked (81740 bytes of `dist/*.js`, 26605 bytes of `dist/*.d.ts`, 3583 bytes of `fixtures/`, 5822 bytes of package-root files), shasum `3bc47df12f21fe7d68336f595d397ff868b3d4d7`.
- `dsh-remedy-core@0.3.8`: 26551 bytes compressed, 21 files, 83461 bytes unpacked (58062 bytes of `dist/*.js`, 22102 bytes of `dist/*.d.ts`), shasum `0df993f85589e101b15b830fa105e7ef8c66c5d5`.

### Notes

- P-0011, P-0012 and P-0013 are `tested`, not `verified`. P-0011 and P-0013 live on a seam a live journal witnesses only when a turn fails in a class this plugin retries, and the retry budget defaults to 0; P-0012 is a build-side gate.
- `agent/pre-step` is deliberately not mounted. The upstream contract is that a rejected step opens no step, but nobody has measured what a user sees when a plugin rejects one, so a mounted refusal would be guessing.
- The `withdrawn` counter was measured unreachable on this host: none of 24 329 persisted attempt streams carried a provable fusion inside a `block-end`, which is what `rolled-back` requires. Blind spot `BS-14` records it.
- The whole `MALFORMED_RESPONSE` corpus on one machine was replayed through the built engine: 47 turns, 39 repaired, 8 refused, and no repaired case dispatched a call whose arguments failed to parse (`data/results/malformed-replay-2026-11-12T11-30-00.000Z.json`). A generated pass of 300000 argument texts asserts the same invariant with a recorded seed (`data/results/stress-repair-2026-11-12T12-10-00.000Z.json`).
- This release is published and is the registry `latest` for both packages; `0.3.7` is the release before it.
