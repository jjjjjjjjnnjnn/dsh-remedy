# P-0017 — The two pages npm renders had no mechanism at all

**Status**: `tested`  **Severity**: minor  **Surface**: `scripts`  **Depends on**: P-0014

## Symptom

`packages/plugin/README.md` and `packages/core/README.md` are the pages npm shows
for each package. Neither was covered by anything:

- `scripts/gate_copy.mjs` covers the outward files at the repository **root**;
  these two live under `packages/`, have no `output_sha256` in
  `docs/copy/manifest.json`, and are not generated by `scripts/copy_record.mjs`.
- `tests/governance/public-copy.test.ts` iterates the same root-level list.
- P-0010 pinned exactly one line (`scan`), and P-0014 pinned the whole CLI **block**.
  Everything else on the plugin page — 2331 bytes of prose — was compared against
  nothing.

That is the same family as P-0004, P-0006, P-0010, P-0014 and P-0016: a fact with
no mechanism. Blind spot `BS-13` had said so for four rounds, each time describing
"the rest of the page" without measuring how big "the rest" was.

## What was measured first

Before adding a mechanism, the size of the exposure was measured with the copy
channel's own rule:

```
node --input-type=module -e "import {proseNumbers} from './scripts/lib/copy-policy.mjs'; ..."
# packages/plugin/README.md: 2331 bytes, prose numbers []
```

**Zero.** Every number on the plugin page is inside a fence or inline code, and those
are exactly what `copy-policy.mjs` strips before it looks. So the number rule — the
rule this project actually enforces on outward text — had nothing left to rot on
this page. What remained was: a fenced command block that a reader copies, and prose
about behaviour.

That measurement is the reason this patch is small: a claim about "the whole page"
turned out to be a claim about one number (there is none) and one block (already
pinned by P-0014).

## What changed

1. `tests/governance/package-readme-prose.test.ts` (new, 2 tests):
   - **no prose number** in either package README, using the same stripping rule as
     `copy-policy.mjs` (fences, inline code, URLs). A number a gate cannot check is
     a number that will go stale, so the page describes things without digits;
   - **every `dsh-remedy <command>` inside a fence** is a command `cli.ts` really
     dispatches, and the engine page must not document a CLI at all (it is a
     library).
2. `packages/plugin/README.md` grew two short paragraphs where the page had been
   silent: the four exit codes are the whole vocabulary and `3` is reserved for
   "cannot read this", and `explain` reads its coverage from the patches themselves
   so a new patch is answered the same day, and never infers a setting.

## What this does not do

- It does **not** move `packages/*/README.md` into the copy channel. Doing that
  would make npm render a generated page, which is a product decision rather than a
  guard; `BS-13` therefore stays open, narrowed to layout and behavioural prose.
- The number rule is the copy channel's criterion, not a truth test: a sentence
  could still describe behaviour the code does not have, and this patch would not
  notice. P-0014 caught one such case by accident (the CLI block), and nothing here
  generalises it.
- The engine page is held to the weaker half only (no prose numbers, no CLI block),
  because it documents a library rather than a command.
- No live artifact is possible: these are package pages, not a resident seam.

## Reproduction

```
node --test tests/governance/package-readme-prose.test.ts    # green
node --test tests/unit/cli-usage.test.ts                     # the block equality from P-0014
node --input-type=module -e "import {proseNumbers} from './scripts/lib/copy-policy.mjs'; console.log(proseNumbers('...'))"
```
