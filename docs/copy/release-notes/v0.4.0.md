## dsh-remedy 0.4.0

### Added

- `dsh-remedy explain` answers a second question the registry alone could not answer: which patch covers a failure class your machine actually hits, and whether that patch is switched on in the profile you point it at. Coverage is declared by the patch (`failureClasses`, `switchKey`) rather than restated by the command, so a patch merged tomorrow is answered the same day.
- `scan` reports every way a turn can end and names every error code, instead of only the repairable ones. On the host this was measured on that surfaced `max_tokens` and `UNSUPPORTED_REASONING_EFFORT`, the two largest classes, neither of which the report had ever mentioned.
- `agent/request-error` gained a written contract and a bounded retry budget, and the deterministic refusals that used to end a turn in silence are now named once per step.

### Changed

- The byte budget is measured per load path — residency, CLI, total — so a mounted daemon and a command invocation no longer compete for one ceiling.
- Outward text is written in the session that does the work, and every prose number in it must exist in the fact pack. The check is no longer "which model typed this".

### Fixed

- A bare, unquoted value after a member key is resealed only when exactly one rewriting proves; otherwise it is refused. A truncated call is never repaired.
- A refusal is observable: a stream whose only defect is bad JSON reads quiet, a proven fusion that was declined reads refused, and neither is reported as an attempted repair.
- `scan` reads multi-frame zstd logs instead of counting compressed bytes as unreadable lines, and a session header is dated by its `createdAt` rather than reported as unreadable.
- The npm page documents every command the binary dispatches, including `explain`, and the usage block is compared line for line with the CLI's own text.
- The project's own description is checked instead of trusted: the fact pack's version and pins must match the manifests, the handoff's evidence index must resolve against the files it cites, and the pack's own statements must hold.
- The publish wrapper names a Windows access violation for what it is, instead of printing a bare exit code and offering HTTP advice for a process that never spoke to the registry.

### Package size

- core: 31773 bytes compressed, 21 files, 100304 bytes unpacked, shasum `48d449b75bb7fa06f4bc16181433e617d2ca5a66`.

### Notes

- Seven patches in this release are `tested`, not `verified`: they touch prose, manifests, a build script, offline readers or a measurement on an isolated profile, and no resident journal can witness them. Three earlier patches stay `verified` on a real host.
- `agent/pre-step` is measured but still not mounted. A rejection closes the turn as `blocked` with no step opened and discards the claimed input, so a later patch may use the seam only to rewrite the message. How the desktop renders `blocked` remains unmeasured.
- A mid-stream withdrawal (`withdrawn`) cannot happen on this host: 0 of 24 329 persisted attempt streams carry a provable fusion inside a `block-end`, which is what `rolled-back` requires.
- `0.3.8` is the previous release and shipped thirteen patches. This release adds the seven merged since, and it was verified by installing it into a cold directory from the registry: `dsh-remedy verify` printed `OK 6 fixture(s)`.
