## dsh-remedy 0.4.13

### Added

- **P-0042 — the profile and the refusal never met, and the seam cannot move the level.** The host
  refused `reasoningEffort: "xhigh"` 37 times across eleven sessions while the profile still fixed
  that level: `scan` had the count, the profile had the level, and nothing compared them. `scan` now
  keeps `provider/model level` for a refusal the host itself named, and
  `explain --sessions … --profile-file …` prints one `CONFLICT` line and exits 1 when the profile
  still fixes exactly that level. Nothing is clamped and nothing is rewritten: the choice stays the
  user's (P-0013).
- The shape came from a measurement, not a preference. `agent/pre-step` `{kind:"enter"}` is admitted
  by the host — the added message becomes a real `user/message` and the turn completes — but it
  cannot change a selection the loop fixed, so the same rewrite on `xhigh` still dies in
  `prepareCall`. `reject` stays disqualified on the desktop profile, where the window draws it as a
  completed turn. Four isolated runs are recorded in
  `data/results/prestep-enter-2026-11-15T17-55-00.000Z.json`.

### Fixed

- `record_live_mount.mjs` carried `dsh_version: '0.2.2-rc.1'` as a literal, so every artifact it
  wrote from the runtime upgrade onward named a version that had not run. It now reads the version
  from the runtime's own `runtime.json` and records that file's hash beside it. The desktop
  artifact of this round is the first one that says `0.2.2-rc.3` because the file says so.
- A helper in `explain-command.ts` that nothing called is deleted; the CLI budget paid for the new
  field by dropping dead code and duplicated prose, not by moving a cap.

### Changed

- `session-scan` reports one new field, `refused_efforts`; it stays empty unless the host's own
  sentence names provider, model and level, so a bare code never becomes a guessed level.
- The emitted prose in five CLI modules was compacted to pay for the addition; the caps did not move.
