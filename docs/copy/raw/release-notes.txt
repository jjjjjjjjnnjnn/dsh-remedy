## dsh-remedy 0.4.5

### Fixed

- The packaged fixtures no longer carry this machine's home path. `fixtures/toolcall-fusion/session-9045e2ec-seq-526.json` quotes the shell command a real session ran, and that command began with the account's workspace, so every tarball since the first release shipped the account name. The account segment is now `<home>` — the same placeholder the redactor writes — and the fixture's own note says the file is no longer a byte-for-byte copy and why. Reported by the dshopen maintainer while accepting the plugin (`polang233/dsh-plugin-index#472`).
- `scripts/record_adaptation.mjs` redacts the runtime path it records, and the public repository stops naming the account in six patch docs, the handoff, one step review and one adaptation artifact.

### Added

- `tests/governance/shipped-samples.test.ts`: no file that ships in a tarball, and no page npm renders, may contain an absolute `…:/Users/<name>` segment. It walks the canonical **and** packaged fixture directories plus the outward pages, and it carries an injected sample so a regex typo fails instead of passing quietly.
- `packages/plugin/README.zh.md`: the Chinese page for the plugin, so the market card that reads the package directory has Chinese content and not only English.

### Changed

- The market entry's description is one sentence per language instead of a paragraph, and the plugin page opens with what the plugin is for rather than with how it is built.

### Notes

- This release carries 28 patches: 3 `verified` and 25 `tested`.
- Redaction still happens where data is produced. What changed is that the corpus it was produced into is now checked on the way out — the fixture survived six releases because a hand-checked-in file has no writer to redact it.
- A cold directory installed `dsh-remedy@0.4.5` from the registry and `dsh-remedy verify` printed `OK 6 fixture(s)`.
