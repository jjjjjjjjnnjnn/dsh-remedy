## dsh-remedy 0.4.2

### Fixed

- P-0025: `dsh-remedy explain` no longer reports an unread profile as a finding. Run with `--sessions` and no `--profile-file`, it printed `(no)` in the "enabled here" column for every covered class and exited `1` — a finding about a profile nobody had read — while the same screen ended with `enabled-here is unknown`. The column now has three states: the coverers, `(no)` for a profile that switches them off, and `unknown` when no profile was named. Only a profile that was actually read can make the command exit `1`, and the exit code uses the same `EXIT_FINDING` constant the other commands use.
- P-0026: the release procedure has one home. `docs/HANDOFF.md` still taught the pnpm filter publish path and an OTP requirement, and its boundary section said the profiles pointed at a `0.3.5` tarball and that the registry `latest` was `0.3.5`. The handoff now points at `docs/PUBLISH.md`, and `tests/governance/release-procedure.test.ts` refuses the retired commands, any flag `scripts/publish_packages.mjs` does not read, and a boundary statement that cites a gitignored `.tmp/` path or a `latest` the packages do not ship.

### Added

- Two new judgements instead of two new promises: `tests/governance/release-procedure.test.ts` (the release procedure has one home, the publish flags named in the docs are the ones the script reads, and the handoff boundary section cites no gitignored path or stale `latest`) and three cases in `tests/e2e/explain.test.ts` that pin the three states of the `enabled here` column.

### Changed

- P-0024: the two package READMEs are live entries in the copy channel. `gate_copy` checks their bytes, their fact-pack hash, their prose numbers and their writer, and requires both entries; the P-0017 prose test stays as a second guard. The pages are still hand-written and still ship inside the tarball, so a change to them reaches npm only with a release.
