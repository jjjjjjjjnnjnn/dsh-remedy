## dsh-remedy 0.4.7

### Fixed

- **The engine every mount loads had no byte budget.** P-0012 recorded that `dsh-remedy-core` sits outside the size gate, and a governance test called it "a separate package with its own budget", but no cap existed: the plugin half was down to 87 bytes of headroom while the engine had grown to 100190 emitted bytes — 66303 of them `registry.js`, which gains a record per patch.

### Added

- `CORE_CAP = 104000` and `registry.js <= 68000` in `scripts/lib/budgets.mjs`, with the measured pair and the owner's in-session signature recorded beside them.
- `gate_size` measures `packages/core/dist/*.js`, reports `core-total` and `core-file:registry.js`, and `handoff-bytes` compares the live handoff's core row with the measurement.
- `tests/governance/budget-split.test.ts` pins the constants, the recorded measurement and the rule that the registry cap fits inside the engine cap.

### Changed

- The startup account is two rows read together now — plugin and engine — instead of one number that described only the plugin. Core is still not folded into `residency`; the patch records that as a limit rather than pretending the number changed shape.

### Package size

- `dsh-remedy@0.4.7`: 39878 bytes compressed, 36 files, 126519 bytes unpacked (82913 of `dist/*.js`), shasum `6c1a19a8…`.
- `dsh-remedy-core@0.4.7`: 40504 bytes compressed, 23 files, 129511 bytes unpacked (100190 of `dist/*.js`), shasum `68931b34…`.

### Notes

- This release carries 31 patches: 3 `verified` and 28 `tested`.
- Byte budget: plugin residency 41551 of 44000, CLI 41362 of 42000, total 82913 of 83000 (87 bytes of headroom); engine 100190 of 104000, `registry.js` 66303 of 68000. No existing cap moved; one was added.
- The registry cap leaves less than one record of headroom on purpose: the next record is paid by splitting the registry by seam or by a signed raise, so registry data cannot silently eat the engine.
- Measured on DSH 0.2.2-rc.3 (Windows). The supported range is unchanged.
