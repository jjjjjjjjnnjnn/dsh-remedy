## dsh-remedy 0.4.19

### Added

- **P-0053 — a chunk this plugin cannot read is passed through, not turned into its own
  exception.** A neighbouring plugin can hand the `llm/stream` wrapper a `null` chunk, a
  `block-end` whose `arguments` is not a string, a `block-end` with no `block`, or a
  `finish` with no `reason`. On the 0.4.18 bytes each of those ended the turn with a
  `TypeError` raised by this plugin. The wrapper now checks only the fields it reads;
  on the first foreign chunk it flushes the tail it already holds and then only passes the
  rest of that stream through. A provider failure that arrives afterwards is still counted
  as an error.
- **P-0054 — the fallback name is not borrowed when the profile already owns it.**
  `remedy_unattributed` is a name this plugin sends a call to when it cannot prove the
  tool; if `options.tools` already declares that name, a rescue is abandoned whole and the
  provider's original failure goes back. The same rule now covers the second dispatch
  site: a `block-end` with no tool name keeps its own bytes instead of borrowing that
  name.

### Changed

- The `llm/stream` wrapper's contract is now written down in ADR 0002: a stream may only
  pass through, be repaired where a fusion is proven, or rethrow the provider's failure.

### Fixed

- Two `TypeError`s that were reachable from a neighbour's shape no longer end a turn.
- A repaired fragment can no longer be dispatched into a profile tool that happens to be
  named `remedy_unattributed`.

### Package size

- `dsh-remedy@0.4.19`: 36666 bytes compressed, 38 files, 121801 bytes unpacked.
- `dsh-remedy-core@0.4.19`: 39297 bytes compressed, 29 files, 129673 bytes unpacked.
