## dsh-remedy 0.4.4

### Fixed

- A fused text that glues two calls of **different** tools no longer calls the wrong tool. The stream carries one tool name for that index, so fragments after the first inherited it; measured twice on DSH 0.2.2-rc.3, the surplus object `{"command":"Get-ChildItem …"}` was dispatched as `read` and the tool answered `invalid arguments: missing required property "file_path"`. The wrapper now receives the request's tool declarations and checks each synthesized fragment against the named tool's `required` fields; one that does not fit goes out as `remedy_unattributed`, which the runtime answers with `UNKNOWN_TOOL` while the turn continues. The `repaired` event records `unattributed: <n>`.
- `BS-18` narrows with it: the wrong dispatch became a named failure the model can retry. What stays open is a tool whose declaration proves nothing — no `required` list means no claim, so its fragments keep the stream's name.

### Changed

- The resident half paid for the patch itself. The first build was 2 539 bytes over the 83000-byte total, so `repair-stream.ts` prose was condensed in four passes and `toolsOf` was inlined into its single call site. No cap moved.

### Added

- `tests/unit/attribution.test.ts`: six tests written before the change — cross-tool (red first), same-tool, no declarations, an empty `required` list, the `unattributed` count on the event, and the measured same-tool fixture as a regression guard.
